# Workspace close skips the check for open TODOs

- **Severity:** Medium. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-28, from the branch `calummoore/do-not-open-pr-planning-aesi`, review round 1, the check of finding 4.
- **Location:**
  - `skills/delegating/SKILL.md`: "Check, merge, and continue", steps 1 to 3.
  - `skills/delegating/references/workspaces.md`: "Read the result and request changes", and "Integrate and close" from "After the last merge, close the work item" to the paragraph that starts "Delete the branch on the remote".
- **Reason:** The steps that close a workspace without this check were the same on `origin/main` before the branch that found the problem, and that branch's review covered only its diff.

- **Terms:**
  - **Orchestrator:** the session that manages a plan. It delegates each work item to a workspace and merges the results into the primary branch.
  - **Work item:** a milestone, or a group of TODOs in one milestone, that one workspace does. The orchestrator names its TODOs in the workspace prompt, and the workspace agent adds `Branch:` and its branch to those TODO lines.
  - **Primary branch:** the branch of the plan. Workspace branches merge into it.
  - **Partial handoff:** a workspace report in which a TODO of the work item is still open.
- **Background:**
  - Since 2026-11-28, a workspace agent opens its pull request into the primary branch only when its work item is complete. When a TODO stays open, the workspace prompt (`skills/delegating/templates/workspace-prompt.md`, step 5) tells it to report its branch, its commit, and each open TODO with its blocker. The close step in `workspaces.md` then checks the merge with `git merge-base --is-ancestor origin/<branch> HEAD` in place of the `gh pr` lines.
  - "Implementing a plan" in the `plans` skill says: "Check each delegated result against the milestone's TODOs and the repository rules. Request changes until it passes. Then tick the TODO." That rule is about the result of each TODO. It does not say what to do with a work item whose TODOs are not all done.
  - "Check, merge, and continue" step 1 confirms every ticked TODO and the push. Step 2 merges the branch and starts the milestones that depend on it. Step 3 closes the workspace after the last fix-round merge. Step 3 also sends an abandoned workspace through the same close step.
- **Problem:** No step confirms that every TODO of the work item is ticked before step 2 starts the dependent milestones or step 3 closes the workspace. Step 1 checks only the TODOs that are ticked. A partial handoff can therefore pass as a complete one.
- **Impact if no action:** A dependent milestone can start on incomplete work, and the workspace that holds the context of the open TODOs can be archived.
- **Root question:** How does the orchestrator know that a work item is complete before it starts the dependent milestones or closes the workspace?
- **Options:**
  - **A.** In step 2, before the orchestrator starts the dependent milestones, and in step 3, before it closes the workspace, it confirms that each TODO of the work item is ticked. The TODOs of the work item are the TODOs that the workspace prompt named, not only the lines with `Branch:`. When a TODO stays open, the branch still merges, as step 5 allows, but the dependent milestones wait, and the orchestrator sends the open TODOs back to the same workspace, as "Read the result and request changes" says. Only the user can move an open TODO out of the work item, or abandon it. Cost: two sentences in the skill and one in the reference. Risk: none, because the check reads the plan and the prompt, which the orchestrator already has. Effort: Small.
  - **B.** Do A, and add a field for the open TODOs to each entry of the ledger, the file `.context/<plan-name>/workspaces.md` that the orchestrator keeps for each workspace. `workspaces.md` lists the ledger fields in its first section. Cost: one more field that the orchestrator must keep current. Effort: Small.
- **Left out:**
  - A script that parses the plan for unticked TODOs is left out. It adds a new check, which the outcome rules of the `decisions-and-findings` skill block without the user. A is a step in the orchestrator's procedure, not a check that fails a run.
  - Treating the pull request as the sign of a complete work item is left out. A workspace on an install that did not update, or a pull request that the user opens by hand, gives a pull request for a partial item.
- **Wider fix:** A. One step at the receiving end catches a partial handoff in any form: a report with open TODOs, or a pull request for a partial item.
- **Previous examples:** None found.
- **Related:** `plans/follow-ups/multi-pr-plan-rules-have-no-owner.md`. Both items edit `skills/delegating/SKILL.md` ("Check, merge, and continue") and `skills/delegating/references/workspaces.md` ("Integrate and close"). Make the two edits in one branch, or rebase the second.
- **Recommendation:** A. It closes the gap in three sentences, and B adds a record to keep current.
- **Action:** fix after merge, apply A, because the steps were the same before the branch that found it, and its review covered only its diff.
